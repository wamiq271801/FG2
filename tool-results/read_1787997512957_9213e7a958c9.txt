   830→- dynamic portions inside cached trees
   831→

   834→Do NOT force the entire route static.

   844→14. HEADER NAVIGATION LOADER — STRICT UX REQUIREMENT
   845→============================================================
   846→
   847→The existing header loader UI MUST NOT CHANGE.
   848→
   849→DO NOT change:
   850→
   851→- appearance
   852→- color
   853→- position
   854→- thickness
   855→- dimensions
   856→- animation
   857→- easing
   858→- duration
   859→- styling
   860→- visual behavior
   861→
   862→Only change the underlying lifecycle/state logic if required.
   863→
   864→The loader must behave like a high-quality dashboard navigation progress indicator.
   865→
   866→DESIRED BEHAVIOR:
   867→
   868→Every USER-INITIATED client-side navigation:
   869→
   870→    click
   871→      ↓
   872→    navigation starts
   873→      ↓
   874→    existing header loader lifecycle starts immediately
   875→      ↓
   876→    actual navigation/RSC work
   877→      ↓
   878→    destination commits
   879→      ↓
   880→    existing header loader completes
   881→
   882→IMPORTANT:
   883→
   884→The loader should NOT only appear for slow pages.
   885→
   886→It should start for EVERY actual navigation.
   887→
   888→However, for an instant navigation, it should complete so quickly that the user may barely see it or not see a visible flash.
   889→
   890→For a slow navigation, it should remain visible until the real navigation completes.
   891→
   892→Example:
   893→
   894→    click
   895→      ↓
   896→    start progress
   897→      ↓
   898→    page commits in 10ms
   899→      ↓
   900→    complete progress
   901→
   902→versus:
   903→
   904→    click
   905→      ↓
   906→    start progress
   907→      ↓
   908→    page still loading after visual threshold
   909→      ↓
   910→    existing loader becomes visibly active
   911→      ↓
   912→    page commits
   913→      ↓
   914→    complete progress
   915→
   916→A small reveal threshold is allowed ONLY to prevent an ugly visual flash.
   917→
   918→The threshold MUST NOT be used as fake navigation completion.
   919→
   920→NEVER:
   921→
   922→    start()
   923→    setTimeout(complete, 500)
   924→
   925→Navigation completion MUST be tied to the actual navigation lifecycle.
   926→

   929→15. PREFETCH VS ACTUAL NAVIGATION
   930→============================================================
   931→
   932→Background prefetch is NOT the same thing as user navigation.
   933→
   934→The header loader MUST NOT appear simply because Next.js is prefetching links in the background.
   935→
   936→Desired:
   937→
   938→    background Link prefetch
   939→       ↓
   940→    no header loader
   941→
   942→Actual click:
   943→
   944→    user click
   945→       ↓
   946→    navigation
   947→       ↓
   948→    header loader
   949→
   950→
   951→Inspect the current custom Link/useLinkStatus implementation.
   952→
   953→Determine whether `useLinkStatus()` is being used in a way that incorrectly turns background prefetch activity into global navigation loading.
   954→
   955→Use the current official Next.js navigation APIs appropriately.
   956→
   957→Do not disable prefetch globally.

   961→16. CONCURRENT NAVIGATION STATE
   962→============================================================
   963→
   964→If the existing implementation uses a global boolean:
   965→
   966→    pending: boolean
   967→
   968→and multiple link/navigation reporters can overlap, replace it with the simplest correct reference-counted model if required.
   969→
   970→Conceptually:
   971→
   972→    start:
   973→        pendingCount += 1
   974→
   975→    complete:
   976→        pendingCount = Math.max(0, pendingCount - 1)
   977→
   978→    pending:
   979→        pendingCount > 0
   980→
   981→The exact implementation must be based on the current repository.
   982→
   983→Do not blindly introduce a counter if the current Next.js API provides a more accurate lifecycle mechanism.
   984→
   985→The requirement is:
   986→
   987→- concurrent operations must not race
   988→- one completion must not cancel another active navigation
   989→- stale/unmounted reporters must not permanently leave the loader active
   990→- actual navigation completion must always be able to clear the loader
   991→
   992→If pathname change is useful as a safety signal, use it carefully.
   993→
   994→Do NOT blindly reset all navigation state on every pathname change if that can break legitimate concurrent state.
