    47→    47→    47→# 2. Core Architecture
    48→    48→    48→
    49→    49→    49→## Storefront
    50→    50→    50→
    51→    51→    51→Next.js App Router.
    52→    52→    52→
    53→    53→    53→The storefront is primarily static and server-rendered.
    54→    54→    54→
    55→    55→    55→Catalog and SEO pages use SSG and ISR.
    56→    56→    56→
    57→    57→    57→User-specific pages use static server-rendered shells. Only the interactive or user-data areas become Client Components.
    58→    58→    58→
    59→    59→    59→All important visible text must exist in the server-rendered HTML.
    60→    60→    60→
    61→    61→    61→Do not turn an entire page into a Client Component because one form, filter, button, or interactive section needs client code.
    62→    62→    62→
    63→    63→    63→The browser hydrates the required interactive components after the HTML is rendered.
    64→    64→    64→
    65→    65→    65→The frontend communicates directly with Supabase for normal reads and standard RLS-protected user-owned operations.
    66→    66→    66→
    67→    67→    67→The frontend communicates directly with the Cloudflare Worker only for sensitive actions that require server-side authority.
    68→    68→    68→
    69→    69→    69→The frontend communicates directly with the tracking ingest backend for batched tracking events.
    70→    70→    70→
    71→    71→    71→The frontend never communicates with TiDB.
    72→    72→    72→
    73→    73→    73→The frontend never communicates with the tracking processor.

   153→   153→   153→
   154→   154→   154→The home page remains static/ISR.
   155→   155→   155→
   156→   156→   156→The tracking processor prepares compact circulation results in Supabase.
   157→   157→   157→
   158→   158→   158→The home page consumes the latest published ready data.
   159→   159→   159→
   160→   160→   160→```text
   161→   161→   161→TRACKING PROCESSOR
   162→   162→   162→        │
   163→   163→   163→        ▼
   164→   164→   164→SUPABASE READY RESULTS
   165→   165→   165→        │
   166→   166→   166→        ▼
   167→   167→   167→NEXT.JS ISR
   168→   168→   168→        │
   169→   169→   169→        ├── Read current products
   170→   170→   170→        ├── Read offers
   171→   171→   171→        ├── Read categories
   172→   172→   172→        └── Read published circulation results
   173→   173→   173→                │
   174→   174→   174→                ▼
   175→   175→   175→          Render complete HTML
   176→   176→   176→```
   177→   177→   177→
   178→   178→   178→Circulation results contain selection and ordering information, not duplicate product records.
   179→   179→   179→
   180→   180→   180→Next.js combines:
   181→   181→   181→
   182→   182→   182→```text
   183→   183→   183→READY PRODUCT ORDER
   184→   184→   184→+
   185→   185→   185→CURRENT PRODUCT DATA
   186→   186→   186→+
   187→   187→   187→CURRENT OFFER DATA
   188→   188→   188→=
   189→   189→   189→HOME PAGE
   190→   190→   190→```
   191→   191→   191→
   192→   192→   192→Validate that a circulated product is still active and eligible before rendering it.
   193→   193→   193→
   194→   194→   194→Do not recalculate circulation inside Next.js.
   195→   195→   195→
   196→   196→   196→Do not wait for tracking processing.
   197→   197→   197→
   198→   198→   198→If a section has no valid data, do not render that section.
   199→   199→   199→
   200→   200→   200→If circulation data does not yet exist, use a simple stable catalog fallback so the website still works.
   201→   201→   201→
   202→   202→   202→Do not recreate the circulation algorithm as a fallback.
   203→   203→   203→
   204→   204→   204→The last successful published result remains usable if processing fails.

   308→   308→   308→# 9. Authentication
   309→   309→   309→
   310→   310→   310→Supabase Auth is the authentication authority.
   311→   311→   311→
   312→   312→   312→The Worker is only a thin protection gate for selected abuse-prone entry points.
   313→   313→   313→
   314→   314→   314→The Worker does not own authentication state.
   315→   315→   315→
   316→   316→   316→The Worker does not own OTP state.
   317→   317→   317→
   318→   318→   318→The Worker does not create custom JWTs.
   319→   319→   319→
   320→   320→   320→The Worker does not manage token refresh.
   321→   321→   321→
   322→   322→   322→The Worker does not wait for users.
   323→   323→   323→
   324→   324→   324→The full authentication flow is:
   325→   325→   325→
   326→   326→   326→```text
   327→   327→   327→USER SUBMITS REGISTRATION
   328→   328→   328→        │
   329→   329→   329→        ▼
   330→   330→   330→CLOUDFLARE WORKER
   331→   331→   331→        │
   332→   332→   332→        ├── Validate request
   333→   333→   333→        ├── Rate limit
   334→   334→   334→        ├── Lightweight abuse checks
   335→   335→   335→        └── Call Supabase Auth
   336→   336→   336→                │
   337→   337→   337→                ▼
   338→   338→   338→             RETURN
   339→   339→   339→
   340→   340→   340→USER MAY TAKE MINUTES
   341→   341→   341→TO COMPLETE VERIFICATION
   342→   342→   342→        │
   343→   343→   343→        ▼
   344→   344→   344→BROWSER ↔ SUPABASE AUTH
   345→   345→   345→        │
   346→   346→   346→        ▼
   347→   347→   347→SESSION ESTABLISHED
   348→   348→   348→        │
   349→   349→   349→        ▼
   350→   350→   350→ONBOARDING
   351→   351→   351→        │
   352→   352→   352→        ▼
   353→   353→   353→SUPABASE + RLS
   354→   354→   354→        │
   355→   355→   355→        ▼
   356→   356→   356→ONBOARDING COMPLETE
   357→   357→   357→```
   358→   358→   358→
   359→   359→   359→Each request is independent.
   360→   360→   360→
   361→   361→   361→The Worker must return after completing the registration request.
   362→   362→   362→
   363→   363→   363→It must never wait for OTP entry.
   364→   364→   364→
   365→   365→   365→It must never hold an onboarding session open.
   366→   366→   366→
   367→   367→   367→OTP verification uses Supabase Auth.
   368→   368→   368→
   369→   369→   369→Session persistence and token refresh use the Supabase SDK.
   370→   370→   370→
   371→   371→   371→The application uses authentication state changes to handle sign-in and sign-out.
   372→   372→   372→
   373→   373→   373→When an authenticated session becomes invalid, clear private account-scoped client state and redirect to the sign-in flow.

   646→   646→   646→# 18. Order Creation
   647→   647→   647→
   648→   648→   648→Order creation always goes through the Cloudflare Worker.
   649→   649→   649→
   650→   650→   650→The browser does not send a trusted total.
   651→   651→   651→
   652→   652→   652→The browser does not send trusted prices.
   653→   653→   653→
   654→   654→   654→The browser does not decide whether an offer is valid.
   655→   655→   655→
   656→   656→   656→The Worker performs the authoritative checkout operation.
   657→   657→   657→
   658→   658→   658→```text
   659→   659→   659→PLACE ORDER
   660→   660→   660→        │
   661→   661→   661→        ▼
   662→   662→   662→WORKER
   663→   663→   663→        │
   664→   664→   664→        ├── Authenticate request
   665→   665→   665→        ├── Validate request
   666→   666→   666→        ├── Rate/abuse checks
   667→   667→   667→        ├── Idempotency check
   668→   668→   668→        ├── Read authoritative cart
   669→   669→   669→        ├── Verify selected address ownership
   670→   670→   670→        ├── Verify products
   671→   671→   671→        ├── Verify availability
   672→   672→   672→        ├── Recalculate prices
   673→   673→   673→        ├── Revalidate offers
   674→   674→   674→        └── Calculate final total
   675→   675→   675→                │
   676→   676→   676→                ▼
   677→   677→   677→        ATOMIC ORDER CREATION
   678→   678→   678→                │
   679→   679→   679→                ├── Create order
   680→   680→   680→                ├── Create order items
   681→   681→   681→                ├── Snapshot prices
   682→   682→   682→                ├── Snapshot product details required for history
   683→   683→   683→                ├── Snapshot delivery address
   684→   684→   684→                └── Update purchased cart state
   685→   685→   685→                        │
   686→   686→   686→                        ▼
   687→   687→   687→                    SUCCESS
   688→   688→   688→```
   689→   689→   689→
   690→   690→   690→Clear local cart state only after confirmed success.
   691→   691→   691→
   692→   692→   692→Use idempotency to prevent duplicate orders caused by retries, double-clicks, or uncertain network responses.
   693→   693→   693→
   694→   694→   694→A repeated successful request with the same checkout idempotency key must return the existing successful result rather than create another order.
   695→   695→   695→
   696→   696→   696→The Worker must perform only the required work and complete the request efficiently.
   697→   697→   697→
   698→   698→   698→Do not turn order creation into a multi-request workflow.
   699→   699→   699→
   700→   700→   700→---
   701→   701→   701→
   702→   702→   702→# 19. Order and Address Snapshots
   703→   703→   703→
   704→   704→   704→Orders must preserve historical truth.
   705→   705→   705→
   706→   706→   706→The delivery address is copied into the order when the order is created.
   707→   707→   707→
   708→   708→   708→Later editing or deleting the user's saved address must not change historical orders.
   709→   709→   709→
   710→   710→   710→Product and price information required to represent the historical order is also snapshotted.
   711→   711→   711→
   712→   712→   712→Do not rebuild old order totals from current product prices.
   713→   713→   713→
   714→   714→   714→Do not make old orders depend on the current product record remaining unchanged.
   715→   715→   715→

   806→   806→   806→The Worker must not proxy normal catalog reads.

   808→   808→   808→The Worker must not proxy normal profile, cart, wishlist, or address operations.

   859→   859→   859→
   860→   860→   860→# 24. Frontend Event Collection
   861→   861→   861→
   862→   862→   862→Do not send one request per event.
   863→   863→   863→
   864→   864→   864→Events enter a bounded browser queue.
   865→   865→   865→
   866→   866→   866→The queue batches events and sends them efficiently.
   867→   867→   867→
   868→   868→   868→Each event has a unique event ID.
   869→   869→   869→
   870→   870→   870→If delivery fails:
   871→   871→   871→
   872→   872→   872→```text
   873→   873→   873→KEEP EVENT
   874→   874→   874→        │
   875→   875→   875→        ▼
   876→   876→   876→RETRY LATER
   877→   877→   877→```
   878→   878→   878→
   879→   879→   879→Use controlled retry behavior.
   880→   880→   880→
   881→   881→   881→Do not retry forever.
   882→   882→   882→
   883→   883→   883→Do not allow unlimited browser storage.
   884→   884→   884→
   885→   885→   885→Do not block navigation waiting for analytics.
   886→   886→   886→
   887→   887→   887→Low-value events may be discarded when the bounded queue reaches its limit.
   888→   888→   888→
   889→   889→   889→The tracking endpoint must remain lightweight.
   890→   890→   890→
   891→   891→   891→---
   892→   892→   892→
   893→   893→   893→# 25. Tracking Ingest Backend
   894→   894→   894→
   895→   895→   895→Host the tracking ingest API on Render.
   896→   896→   896→
   897→   897→   897→Its responsibility is only:
   898→   898→   898→
   899→   899→   899→```text
   900→   900→   900→Receive batch
   901→   901→   901→Validate batch
   902→   902→   902→Deduplicate
   903→   903→   903→Bulk insert into TiDB
   904→   904→   904→Return
   905→   905→   905→```
   906→   906→   906→
   907→   907→   907→It does not calculate metrics.
   908→   908→   908→
   909→   909→   909→It does not calculate circulation.
   910→   910→   910→
   911→   911→   911→It does not write raw events to Supabase.
   912→   912→   912→
   913→   913→   913→It remains stateless.
   914→   914→   914→
   915→   915→   915→Use efficient asynchronous request handling and bounded database concurrency.
   916→   916→   916→
   917→   917→   917→Do not add Redis, Kafka, RabbitMQ, or another queue.
   918→   918→   918→

   920→   920→   920→

   922→   922→   922→
   923→   923→   923→# 26. TiDB Event Storage
   924→   924→   924→
   925→   925→   925→TiDB stores raw tracking events.
   926→   926→   926→
   927→   927→   927→Events are append-oriented and indexed for incremental processing.
   928→   928→   928→
   929→   929→   929→Each event has:
   930→   930→   930→
   931→   931→   931→```text
   932→   932→   932→Internal ordered event key
   933→   933→   933→Unique event ID
   934→   934→   934→Event type
   935→   935→   935→Occurred time
   936→   936→   936→Received time
   937→   937→   937→Relevant product/category identifiers
   938→   938→   938→Minimal user/session context when required
   939→   939→   939→```
   940→   940→   940→
   941→   941→   941→Store only data required for analytics and circulation.
   942→   942→   942→
   943→   943→   943→Do not store unnecessary PII.
   944→   944→   944→
   945→   945→   945→Do not store huge browser payloads.
   946→   946→   946→
   947→   947→   947→Do not store complete request headers.
   948→   948→   948→
   949→   949→   949→Do not store redundant data repeatedly.
   950→   950→   950→
   951→   951→   951→Raw events must have a retention strategy so the event store does not grow forever.
   952→   952→   952→
   953→   953→   953→---
   954→   954→   954→
   955→   955→   955→# 27. Incremental Tracking Processor
   956→   956→   956→
   957→   957→   957→Host the processor separately on Render.
   958→   958→   958→
   959→   959→   959→Cron wakes it when processing is required.
   960→   960→   960→
   961→   961→   961→The processor never scans the full event history repeatedly.
   962→   962→   962→
   963→   963→   963→Use a persistent checkpoint.
   964→   964→   964→
   965→   965→   965→```text
   966→   966→   966→CHECKPOINT
   967→   967→   967→        │
   968→   968→   968→        ▼
   969→   969→   969→READ ONLY EVENTS AFTER CHECKPOINT
   970→   970→   970→        │
   971→   971→   971→        ▼
   972→   972→   972→PROCESS BATCH
   973→   973→   973→        │
   974→   974→   974→        ▼
   975→   975→   975→WRITE RESULTS
   976→   976→   976→        │
   977→   977→   977→        ▼
   978→   978→   978→ADVANCE CHECKPOINT
   979→   979→   979→        │
   980→   980→   980→        ▼
   981→   981→   981→REPEAT UNTIL CAUGHT UP
   982→   982→   982→```
   983→   983→   983→
   984→   984→   984→The checkpoint advances only after the corresponding processing work succeeds.
   985→   985→   985→
   986→   986→   986→Never advance the checkpoint before results are safely persisted.
   987→   987→   987→
   988→   988→   988→Do not load all unprocessed events into memory.
   989→   989→   989→
   990→   990→   990→Process bounded batches.
   991→   991→   991→
   992→   992→   992→The processor must use a persistent lock to prevent overlapping cron runs from processing the same work.
   993→   993→   993→
   994→   994→   994→If another processor run already owns the lock, exit safely.
   995→   995→   995→
   996→   996→   996→The lock must recover after crashes.
   997→   997→   997→
   998→   998→   998→Do not rely on Render local storage for locks or checkpoints.
   999→   999→   999→
  1000→  1000→  1000→---
  1001→  1001→  1001→
  1002→  1002→  1002→# 28. Tracking Processing Output
  1003→  1003→  1003→
  1004→  1004→  1004→The processor turns raw events into compact useful data.
  1005→  1005→  1005→
  1006→  1006→  1006→The processor owns the circulation decisions.
  1007→  1007→  1007→
  1008→  1008→  1008→Next.js does not recalculate scores.

  1011→  1011→  1011→

  1020→  1020→  1020→Do not copy the entire raw event history into Supabase.
  1021→  1021→  1021→
  1022→  1022→  1022→The processor may aggregate multiple event types into compact product-level metrics.
  1023→  1023→  1023→

  1025→  1025→  1025→
  1026→  1026→  1026→# 29. Published Result Safety
  1027→  1027→  1027→
  1028→  1028→  1028→Never expose half-written circulation results.
  1029→  1029→  1029→
  1030→  1030→  1030→The flow is:
  1031→  1031→  1031→
  1032→  1032→  1032→```text
  1033→  1033→  1033→CURRENT PUBLISHED VERSION
  1034→  1034→  1034→        │
  1035→  1035→  1035→        ▼
  1036→  1036→  1036→PROCESSOR BUILDS NEW VERSION
  1037→  1037→  1037→        │
  1038→  1038→  1038→        ▼
  1039→  1039→  1039→WRITE COMPLETE NEW RESULT SET
